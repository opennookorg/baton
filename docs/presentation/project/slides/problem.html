The problem

Every issue has an owner. Finding them is the slow part.

01

The list goes stale

Teams split, people move, code changes hands. An ownership file or wiki page is out of date soon after someone writes it.

02

Issues bounce

A misrouted issue sits in the wrong queue, gets relabelled and waits again before anyone who can fix it sees it.

03

Triage lives in heads

Someone senior reads each new issue to decide where it goes. That knowledge is in their head, not in a system.

Baton does not keep a list. It learns ownership from what gets fixed, and keeps learning when it changes.

Baton

Big projects keep an ownership list: this component belongs to that team. It goes stale. Teams split, people move, code changes hands, and new issues bounce between teams until someone who knows picks them up. Baton replaces the list with something that learns from outcomes.
